# ADR-001: Frontend stack is React + Vite + TypeScript

Date: 2026-09-14. Status: accepted (founder decision in session). Serves FR-4
(partially) and unblocks FR-10.

## Context

The call-sheet viewer was a single vanilla HTML file: no build step, a
hand-written service worker, IndexedDB for the last fetched sheet. That was
right for a skeleton that proved the offline behaviour. The next item is
the AD editor (FR-10): forms, a draft kept locally across network loss,
reordering scenes, publish states (unsaved, publishing, published as REV
B). Hand-written DOM code for that grows expensive after the second
screen.

## Options

1. Stay vanilla for the editor too. Zero dependencies; every further
   screen costs more; a rewrite becomes likely within weeks.
2. React + Vite + TypeScript, single-page app. Components and typed API
   shapes; `vite-plugin-pwa` generates the service worker and manifest;
   GitHub Pages builds it in Actions. One build step in CI; the viewer is
   rewritten (about 300 lines) with the existing Playwright tests as the
   behavioural contract.
3. Next.js (the old repository's framework). Familiar to the founder, but
   the app needs no server rendering; static export on Pages adds routing
   friction; more framework than the problem.

## Decision

Option 2. Rewritten the same day, before the editor exists, so the editor
is built once in the target stack. Behaviour parity is proven by the eight
Playwright tests passing unchanged in intent (root shows the demo, share
link loads from an API without a form, dev mode shows the form, offline
and missing-data failure cases, schedule text is never interpreted as
HTML).

## Consequences

- `frontend/` is a Vite project: `npm ci && npm run build` produces `dist/`.
  CI builds before the smoke tests; `pages.yml` builds with
  `VITE_BASE=/filmrunner/`.
- The IndexedDB database and store names are unchanged, so sheets cached
  by phones before the migration remain readable.
- The service worker is generated by Workbox: app shell and the demo are
  precached; public call-sheet reads are network-first with a cache
  fallback. FR-9 (offline-honest status when the worker serves from cache)
  still applies and is easier to solve with Workbox's response metadata.
- API types are hand-written in `src/types.ts` until an OpenAPI-generated
  client is worth it (revisit when the editor adds write calls).

## Revisit when

The editor needs routing beyond query parameters (then add a router, not a
framework), or server rendering becomes a real requirement (then Next.js).
